# S1：token 能不能自動帶入（給工作包 J）

> 2026-10-28。只讀調查，沒有改 repo 裡的程式碼。
> 對象：測試伺服器上實際跑的 DSH `0.2.1-rc.2`（`npx` 安裝在
> `/home/jun/.npm/_npx/1e7f6d9597241db0/node_modules/@deepseek-ai`）。

## 結論（三個問題）

**1. guard 拿不拿得到會話 id？拿得到。**

`ctx.tools.guard((exec) => …)` 的 `exec.agent` 是 DSH 的 Agent 物件，
`exec.agent.id` 就是會話 id（`SessionId`）。這個值跟橋接存在
`state/discord-sessions.json` 裡的 `sessionId` 是同一個（DSH 的 agent id
就是 session id）。`tools/pre-execute`、`tools/execute`、`tools/post-execute`、
`tools/result` 收到的 exec 都有同一個欄位。

**2. 能不能改 `exec` 的參數再放行？guard 不行，`tools/execute` 可以，但那是合約外的做法。**

- guard 裡的 `exec.arguments` 在進入 policy 之前就被 `deepFreeze` 了。
  型別也是 `Readonly<ToolExecution>`。實測賦值直接丟
  `Cannot add property token, object is not extensible`。
- `tools/execute` waterfall 拿到的是還沒凍結的 exec，`next()` 會用同一個
  物件去 dispatch，而工具本體是在 dispatch 當下才讀 `exec.arguments`。
  所以 `exec.arguments = { ...exec.arguments, token }` 再 `next()` 有效（實測成功）。
- 但官方註解寫得很清楚：`tools/execute` wrapper「may change only `exec.signal`」。
  改參數是踩在實作上，不是合約。DSH 一升級就可能失效（見下面的風險）。

**3. 有沒有其他掛點？有四個，只有兩個能改參數，其中只有一個完全走官方 API。**

| 掛點 | 能做的事 | 能不能改參數 |
| --- | --- | --- |
| `tools/pre-execute` waterfall | allow／deny／ask／cancel | 不行，參數同一個凍結物件 |
| `tools/execute` waterfall | 換 signal、換結果；實作上也能換參數 | 可以，但合約只允許 signal |
| `agent.ctx.tools.register` | 每個會話註冊自己的工具，會 shadow 全域同名工具 | 可以，但要自己接一條 MCP 連線 |
| `agent.ctx.plugin(…, config)` | 每個會話掛一個自己的外掛實例 | 可以，等於每個會話一個 mcp-discord 行程 |

另外確認：`mcp-discord` 是 **host 層的單一行程**（`~/.dsh/profiles/web/cordis.patch.yml:40`），
所有會話共用；`dsh-mcp-client` 呼叫 MCP 時只送 `{ name, arguments }`
（`dsh-mcp-client/lib/index.js:140`），沒有任何會話資訊。所以 MCP server
本身永遠不知道呼叫來自哪個會話——這點計畫原本的判斷是對的。

## 實測

在測試伺服器上跑一支獨立腳本（不碰線上 DSH、不呼叫模型）：掛
`dsh-system-prompt` 與 `dsh-tools`，註冊一個假工具、一個 guard、一個
`tools/execute` listener，然後 `ctx.tools.execute(...)` 一次。

```
guard    agentId=ses_probe  argsFrozen=true   mutate → threw: object is not extensible
execute  execFrozen=false   args={"text":"hi"}
execute  mutate exec.arguments → ok
body     args={"text":"hi","token":"injected"}
result   isError=false
```

結論：guard 看得到會話 id、改不了參數；`tools/execute` 改得動，工具本體真的收到新參數。

## 對工作包 J 的建議

### 建議做法（小）：在 `tools/execute` 補 token

> 這一節 2026-10-28 請 Opus 評審後改過。原本只寫「覆寫參數 + 查 token」，
> 補上鎖版本、失敗要炸、拿掉 prompt 裡的 token、以及測試清單。

0. **先把 DSH 鎖版本**：`dsh/run.sh` 的 `npx -y @deepseek-ai/dsh` 改成
   `@deepseek-ai/dsh@0.2.1-rc.2`。沒鎖版本，這個做法會在沒人動手的某次重啟後
   隨機失效；鎖了以後只會在主動升級時失效，升級可以當成一次有意識的變更。
1. 橋接加一個 handler（跟現有 `send`／`react` 同一張表）：`sessionToken`，
   收 `{ sessionId }`，回 `{ token }`。用現成的 `startAgentApi` 與
   `x-agent-token`，不用新機制。`agentSender.tokenFor(sessionId)` 已經存在
   （`src/core/discord-agent.mjs:145`、`:329`），handler 本體只有三行；
   `reverse` 沒有的會話回 404，不提供「列出全部」。
   - 權限代價要寫清楚：現在只拿到 endpoint secret 還發不出訊息（還缺會話 token）；
     加了這個 handler，secret 就等於全部頻道的發送權。dc-chat 沒有檔案／shell 工具，
     secret 不會被模型讀到，所以接受；但 handler 只認活著的會話。
2. 在 `tools/execute` 裡拿 `exec.agent.id` 查快取；沒有就向橋接問一次
   （`POST /sessionToken`），存起來。不需要監聽 `agent/created`：這裡現查最省。
   - 橋接重啟後舊 token 全換，收到 403 就清快取重查，**只重試一次**。
   - 只重試「令牌過期」這一種 403；白名單、額度、會話已結束的 403 不重試。
     用錯誤字串或錯誤碼分清楚，不要看到 403 就重送。
3. 對 `mcp__discord__*`／`mcp__slang__*` 覆寫 `exec.arguments.token`，其他工具直接
   `next()`。**一律覆寫**，不要「有帶才補」：模型被騙也指定不了別的頻道。
4. persona 與工具說明改成「token 不用填」，`mcp-discord` 的 `token` 改成選填。
   選填後必須 fail closed：不帶 token 就拒絕，不要預設值，也不要「只有一個會話」
   就猜一個。
5. 防呆：每次覆寫後讀回 `exec.arguments.token`。不是我們的值就回錯誤結果（不是只記 log），
   讓模型看到「自動帶 token 失效」，而不是送出。這是最小且必要的一層。
   - 想在部署時就發現，可以再加啟動自我測試（註冊一個探測工具 → 覆寫 → 檢查本體收到 →
     移除）。代價是探測工具要暫時列進 guard 白名單，而且註冊／移除會觸發 `tools/change`。
     不做也可以，代價只是第一次呼叫才發現。
6. 收尾：把【發送】行（`src/discord-bridge.js:2471`）的 token 拿掉。
   不然 token 還是會進對話紀錄，也可能被模型貼到頻道。`checkSensitive` 仍要拿
   token 比對，只是它不再出現在 prompt。

成本：外掛約 40 行、橋接一個 handler、`mcp-discord` 的 schema 改選填、`run.sh` 一行。

**最少要測的事**：

1. `mcp__discord__*`／`mcp__slang__*` 的本體收到 `tokenFor(exec.agent.id)`，
   而且蓋掉模型自己填的值。
2. 其他工具參數完全不變，而且 listener 一定會 `next()`。
3. 覆寫沒生效（模擬凍結的 exec）時回錯誤、記 error，不送出。
4. 橋接重啟＝token 過期：403 清快取、重試一次成功；白名單／額度的 403 不重試。
5. dc-learner 或沒有對應會話的呼叫：不帶 token，結果是拒絕。
6. `mcp-discord` 沒有 token 時拒絕，沒有預設值。

### 備援（合約內）：外掛自己註冊工具

如果 A 被 DSH 升級弄壞，換的是這條，不是下面的 B：外掛用 `ctx.tools.register`
直接把 Discord 工具註冊在 preset scope，工具本體用 `exec.agent.id` 加橋接 secret
POST 到橋接，完全不經過 MCP 行程。

- 全部官方 API，不用 restrict、不用多開行程。
- 代價：工具名不再是 `mcp__discord__*`，persona、`DISCORD_TOOLS`、
  `docs/guides/DISCORD.md`、測試都要一起改；schema 要跟 MCP 版共用一個模組。

### 不建議：每個會話自己的 MCP 行程

`agent/created` 時 `agent.ctx.plugin(McpClient, { …, env: { DC_SESSION: agent.id } })`，
讓每個會話自己開一個 `mcp-discord`，server 直接從環境變數知道會話。
`@deepseek-ai/dsh-mcp-client` 是 DSH 內建套件，profile 安裝的外掛可以直接 import。

優點：全部走官方 API（per-agent 註冊、scoped shadow）。
缺點：每個活著的會話多一個 Node 行程。測試伺服器上的 `mcp-discord` 實測 RSS 107 MB
（`mcp-slang` 84 MB），幾十個頻道就是幾 GB；每個會話還要把全域的 `mcp__discord__*`
用 `restrict` 擋掉（`plugins/qq-agent-presets/qq-tool-restrict.mjs:228-238` 有靜默失效的紀錄），
schema 也要自己養一份。

**結論：先做 A，同一個 PR 一起鎖 DSH 版本。** A 失效時換「外掛自己註冊工具」。

## 風險與注意事項

- `run.sh` 用的是 `npx -y @deepseek-ai/dsh`，**沒有鎖版本**。重啟就會抓到新版，
  所以「合約外的參數覆寫」有機會在某次重啟後失效。第 0 點先鎖版本，
  第 5 點的讀回檢查（和可選的啟動自我測試）是第二層。
- 現有 guard 是掛在 preset scope（所有 dc-chat 會話共用），不是每個會話。
  查 token 要在 guard／waterfall 裡用 `exec.agent.id` 現查，不要在外掛載入時查。
- `mcp-discord` 是 host 層的單一行程，`dc-learner` 的會話也連到同一個
  （只是那個 preset 用 `allowDiscordSend: false` 把工具擋掉）。靠設定檔做不到
  「每個會話一個」；第二個做法是外掛自己在會話 scope 再開一個，不是改設定就好。
- `dsh-mcp-client` 在回傳圖片時會用 `exec.agent.session` 判斷模型能不能收圖
  （`dsh-mcp-client/lib/index.js:285-301`）。所以任何「轉手呼叫」的做法都要把
  原本的 exec（含 agent）傳下去，不能自己造一個沒有 agent 的 exec。
- `scripts/dsh-modules.mjs` 在這台 Windows 開發機找不到 DSH（沒有 `~/.dsh`），
  會直接丟錯。這次是直接讀測試伺服器的安裝。要在地端跑相關腳本的話，
  得設 `DSH_MODULES` 或 `DSH_HOME`。
  SSH MCP 行程已經讀過舊設定，要重啟 OpenCode 才會生效；這次是用 `ssh` 指令直接查。
